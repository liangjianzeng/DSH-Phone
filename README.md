# DSH-Phone

> 在 Android 上通过 SSH 隧道访问 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) Web UI 的移动客户端。

DSH-Phone 是一个 Flutter Android 应用：首次启动时配置 SSH 地址 / 用户名 / 认证方式（SSH 密钥或密码），应用自动建立 SSH 隧道（`127.0.0.1:<localPort>` → 远程 `127.0.0.1:3080`），并通过 WebView 加载 DSH Web UI。内置本地缓存加速、SSH 保活、界面缩放与全屏显示、主题自适应，以及手动修改连接配置 / 刷新缓存 / 查看关于的入口。

## 工作原理

```
手机 127.0.0.1:<localPort> ──SSH 隧道──▶ 远程 127.0.0.1:3080 (DSH Web UI)
        ▲                        │
        │  WebView 以 loopback 身份访问
        │  （loopback 为浏览器安全上下文）
```

1. 应用内通过 `dartssh2` 建立 SSH 连接；
2. 把手机本地端口转发到远程 DSH 的 `127.0.0.1:3080`；
3. WebView 加载 `http://127.0.0.1:<localPort>`；
4. 因访问为 loopback，DSH 的模型/设置等特权接口（如 `settings.describe`）也可用。

## 推荐部署方式（公网组网 + SSH 隧道）

云主机上的 DSH 默认只监听 `127.0.0.1:3080`，手机无法直连。推荐用 **Tailscale 组建公网 VPN** 实现公网穿透组网，再经由 VPN IP 走 SSH 隧道穿越：

```
手机 ──Tailscale VPN──▶ 云主机(VPN IP) ──SSH 隧道──▶ 云主机 127.0.0.1:3080 (DSH)
   │                      │
   │                      └── DSH-Phone 配置 SSH 地址为该 VPN IP
   └── WebView 加载 http://127.0.0.1:<localPort> 接入 DSH
```

1. **组网**：手机与云主机均加入同一个 Tailscale 网络（或其它基于 WireGuard 的组网方案），双方获得稳定的 VPN 地址，实现公网穿透、免公网端口映射。
2. **穿越**：DSH-Phone 的 SSH 地址配置为云主机的 **VPN IP**，通过 SSH 隧道把手机本地端口转发到云主机 `127.0.0.1:3080`。
3. **接入**：端侧 WebView 加载 `http://127.0.0.1:<localPort>` 接入云主机 DSH，且以 loopback 身份访问，模型/设置等特权接口可用。

> ⚠️ **跨运营商 UDP QoS 提醒**：Tailscale 走的是 UDP（WireGuard），当手机与云主机**跨运营商**时，运营商往往对 UDP 做 QoS（限速/丢包），会导致 SSH 隧道吞吐骤降，**加载长上下文会话历史时直接超时失败**。同一运营商下通常可达数 MB/s 且不丢包。因此：
> - 建议在**同一运营商网络**下使用（手机与云主机同运营商）；
> - 跨运营商遇到慢/超时，可切换网络、调大页面加载超时，或改用同一运营商线路。

## 功能特性

- 🔐 **首次启动引导**：设置 SSH 地址、端口、用户名，认证方式支持 **SSH 密钥（默认）** 与 **密码**。
- 📦 **多连接实例（最多 3 路）**：配置指向不同服务端的多路 SSH 实例，顶栏状态栏一键自由切换；可为每路实例设置**别名**（最多 7 个中文或 15 个英文字母），顶栏优先显示别名而非地址，避免多路 IP 混淆；敏感信息仍加密存储。
- 🔑 **DSH Token 鉴权适配**：新版 DSH 服务端启用 token 鉴权后，在设置中为实例填入「DSH 访问 Token」（显隐切换、随实例切换回填），访问时自动拼接 `?token=` 换取会话 cookie；仅配置了 token 才拼接（旧版服务保持裸地址直连）；token 变更自动重载重新鉴权；401/403 显示专属提示引导填 Token。
- 🔀 **三服务模式（实例级：DSH 必选主模式 + Zcode / WorkBuddy 可选开关）**：每路实例可分别开启 **Zcode**（转发到远端 `127.0.0.1:8787` 的 **zcode-phone-server** 桥接服务，鉴权链与 DSH 一致）与 **WorkBuddy**（远端 `127.0.0.1:8790`），**DSH**（远端 `127.0.0.1:3080`）恒在。三模式的**远端端口与访问 Token 各自独立存储**（3080 / 8787 / 8790），隧道按当前模式取对应端口。顶栏模式切换入口按**可用模式数**自动变形：只开 DSH 时**不显示**（只有一个模式时不摆"自己切自己"的图标）、两个模式时一键翻转、三个模式时下拉直接选（当前模式打勾）。切换只改转发目标，SSH 会话原样保留、就地生效不断线；远端端口可按机器修改。详见下方 [Zcode 模式与 zcode-phone-server](#zcode-模式与-zcode-phone-server)。
- ⏱️ **可配置页面加载超时**：默认 60s、范围 30–180s，设置页滑块调整；大上下文会话历史加载较慢时可调大。
- 🔄 **自动 SSH 隧道**：基于 `dartssh2` 建立本地端口转发，无需 Root。
- ⚡ **隧道监督器与自愈（单一事实来源）**："重连几次、什么时候报错、要不要整条重建"全部收归 `TunnelService` 决策层，UI 只渲染 `TunnelState` 快照、不自行决策——消除旧实现里界面重试计数与隧道内部状态并发打架（表现为"一直提示连不上、手动重试也没用"）。故障先分类（DNS / 不可达 / 被拒 / 超时 / 认证 / 主机密钥 / 私钥 / 本地端口 / 远端无应答）：链路抖动走**指数退避 0.8s→封顶 60s、带抖动、永不放弃**，配置类错误当场提示去改设置。每 10s SSH keep-alive；每 15s 走**端到端探活**（探本地转发端口，半开/假死连接也能查出来），并区分「SSH 传输层已死」→ 重建 与「远端服务没起」→ 不白重建。本地端口被占时**自己破局**：端口占用绝大多数是自己人没释放干净，于是先回收本进程在用与遗留的监听再重试；仍不通就在**保留段 3090–3099** 里随机借一个端口把隧道跑起来（状态栏如实标注"临时借用保留段"，所有入口都取实际生效端口；设置页禁止把本地端口填进这个段，避免与临时端口互抢），连保留段都用满才停下来让用户换端口——端口占用这类"重试一万次也不会变好"的故障不再空转退避。
- 🩺 **连接诊断（事件流）**：隧道全程记录事件环形缓冲（400 条：建链 / 认证 / 转发 / 探活 / 重建 / 退避），入口 **设置 → 主机 → 连接诊断**（主界面横幅的「详情」也进这里）。真机挂 VPN、没有 adb 时，这是事后定位"到底在哪一步断的"的唯一入口。
- 🔁 **顶栏主动刷新与非阻塞提示**：顶栏连接状态图标即状态（绿=正常 / 橙=抖动或重连中 / 红=配置类失败 / 灰=未连），点一下立即端到端探活、探不通当场强制重建（旧版顶栏没有任何重连入口，假死只能杀 App）。链路不健康时**不弹红色全屏、不显示加载遮罩、不烧页面重试次数**，只在页面顶部挂一条非阻塞横幅，恢复健康后自动补载；WebView 一旦连上即**常驻**，网络闪断不再 dispose 整棵 WebView 导致 SPA 状态全丢、整站重载。
- 🔒 **前台服务后台保活**：隧道需要保持期间（**含重连过程中**，旧实现只在已连接时保活，后台一断就被摘掉唤醒锁、越断越连不上）启动 Android 前台服务（低优先级静默通知 + 唤醒锁），App 进入后台或关屏时进程与网络保持运行、SSH 保活持续发送，恢复前台**不再重连**；滑动清除任务后隧道随任务停止。
- 🚀 **隧道吞吐优化**：本地 fork 的 `dartssh2`（认证后 zlib 压缩 + 整包批量解密），双向透传不做应用层节流，显著提升大体积加载速度。
- 🧭 **WebView 加载 DSH Web UI**：`flutter_inappwebview`，loopback 访问，模型/设置等特权接口可用。
- 💾 **本地缓存加速**：WebView 遵循标准 HTTP 缓存头（服务端 `Cache-Control` 决定资源复用与回源，`no-store` 资源的更新可靠到达手机，修复长期加载旧页面）；主文档请求带 `no-cache`，保证 token→Set-Cookie 鉴权链不被缓存跳过；支持手动清缓存刷新。
- 🔍 **界面缩放**：双指缩放 + 顶栏/设置页 放大、缩小、重置；缩放比例**自动保存**，下次沿用。
- 🎛️ **对话区缩放控件开关**：对话区左侧的放大/缩小/重置浮动按钮默认隐藏，可在设置 → 界面设置中一键开启，避免遮挡内容。
- 📷 **图片直传（视觉工具入口）**：对话区左侧淡蓝色圆形发光相机按钮，一眼即可识别视觉能力；点击拍照/相册选图，自动压缩（≤4096px / 90% 质量）后直传 DSH 消息输入窗口附件槽，支持 png/jpeg/webp/gif；按钮可拖拽并**左右边缘吸附**，单手操作友好；默认开启，设置 → 界面设置可关。
- 🎙️ **语音输入（按住说话）**：对话区**右侧悬浮麦克风图标**（纯图标无底框，默认比月相按钮略高，可拖拽上下移动，空闲时缓慢呼吸提示可用），**长按**即按住说话——sherpa-onnx 流式 Zipformer 端侧识别（模型 ~160MB 首次使用断点续传下载，之后完全离线），实时回显转写、上滑取消、松手注入消息输入框（不自动发送）；浮层为**聆听声浪动效**（音量驱动，引擎就绪前静默等待、无多余提示）；按下时短促"嘀"声提示开始录音。可选**并入相机按钮**（设置 → 语音输入开关）：隐藏麦克风图标，相机按钮右下角叠加麦克风角标（随月相底色自动深浅反色），短按=相机、长按=按住说话。可选**识别增强**档位（beam search + 热词）：内置常用词 + 自定义中文热词优先识别（标准/增强两档均生效，切档自动重启识别）。
- 🌙 **真实月相天文模型**：相机入口按钮按你所在观测位置呈现真实月相（太阳/月球实际位置计算照明度与盘面朝向，含农历日）；观测位置支持默认北京 / 手动经纬度 / GPS 定位（失败自动回退）。
- 🌅 **日出日落联动**：按观测位置的日出日落时刻，白天相机按钮显示全亮（月相暂停），夜间恢复真实月相；本地天文计算无需联网，设置 → 界面设置可关（关闭则始终显示真实月相）。
- 🌦️ **天气动效**：按观测位置经纬度查询真实天气（Open-Meteo 免费数据源，免 API Key；以实测降水量校正雨雪判定，避免无降水误显），在相机按钮周边显示云/雨/雪/雾/雷动效——雨越大动效越强，动效正对相机按钮上方并随按钮拖拽移动、不遮挡对话内容；动效已做**渲染性能优化**（约 20fps 重绘 + 独立合成图层 + 低分配绘制路径），开启后界面依旧流畅；启动时查询一次、之后每小时刷新，设置 → 界面设置可关（默认开启）。
- 📤 **文件上传对话处理**：相机入口选择器新增「选择文件上传」——从手机本地选文件（浏览器/网盘等下载到手机的文件），经 SSH 隧道（SFTP）上传至服务器临时目录（自动探测 home 下 `dsh_phone_uploads/`），并把**服务器本地绝对路径**注入消息输入框；补充指令（如 `/home/u/dsh_phone_uploads/xxx.doc 请阅读后总结输出md`）发送后由云端模型处理，产物再经已有下载能力回传手机，形成"端侧上送 → 云端处理 → 结果下载"闭环；上传大小上限**默认 10M、可配置 1–30M**（设置 → 工具）。
- 📄 **成果查看器（WebView 主渲染 + 原生快速模式）**：点击对话中的成果直接打开预览。HTML / Markdown / CSV / JSON 交给**系统 WebView** 渲染（`loadData` + `baseUrl` 指向隧道 origin）——外链 CSS、字体、表格、报告里的相对路径截图、图表脚本全部可用；代码走原生语法高亮，带**行号 + 横向滚动 + 可选中复制**；CSV 渲染成真正的表格、JSON 自动美化。右上角可一键在「网页渲染 / 原生渲染」之间切换（超长文件用原生更稳）。**图片成果可直接预览**（双指缩放，不再只能下载），SVG 按矢量渲染；状态栏提供**另存为**。
- 🩺 **预览失败可自查**：查看失败不再只留一句红字——失败卡片显示**试过的云端路径/链接**（可选中、一键复制），按失败分类给下一步建议（不存在 / 是目录 / 无权限 / 超时 / SSH 通道耗尽 / 隧道未连 / 文件超大），链接可达时再给「用网页方式打开」兜底；顶栏只留三个高频图标（渲染切换、网页兜底、复制路径等收进 ⋯ 菜单），标题显示**文件名**且支持长按复制「文件名 + 路径 + 链接」，没有 adb 也能把现场说清楚。
- 💾 **编码自动检测**：通过 SFTP 读取云端文件，自动识别 UTF-8 / GBK（GB2312）/ ASCII，中文路径与内容不再乱码。
- 📦 **资源下载（断点续传 + 另存为）**：点击 apk / 压缩包等二进制成果进入下载页，显示进度与大小；支持**暂停 / 继续（断点续传）**、取消、失败重试；续传以已接收字节为准并在完成时校验总大小（截断会明确提示「下载不完整」而非谎报成功），同时最多下载 2 个（避免把远端 SSH 通道占满），已下载完成的任务再次点击**直接复用不重下**；下载完成通过系统文件选择器（SAF）**选择保存位置**。
- 🧩 **隐藏产物与相对路径解析**：DSH 产物 chips 被隐藏时，自动用可见产物的目录 + 文件名拼接并经 SSH 验证定位云端路径；`outputs/报告.md`、`build/app.apk` 这类**相对路径**同样走目录反查（一次 listdir 批量匹配 + 8 秒预算），不再从家目录硬开后报「云端不存在该文件」。
- 🔔 **锁屏任务通知**：AI 智能体任务进行中 / 完成时推送系统通知（依赖前台服务保活，锁屏/熄屏可见，任务完成响铃 + 震动）。
- 📊 **主机监控（10 分钟趋势）**：每 10s 采集远程主机 CPU / 内存 / GPU 使用率 / GPU 温度，顶栏背景显示最近 10 分钟趋势曲线（紫色=GPU 使用率 · 黄色=CPU · 蓝色=内存 · 中国红=GPU 温度）；采集命令对 ARM / 精简 / 容器环境健壮（/proc/stat + /proc/meminfo），Windows 走 PowerShell 性能计数器。

## 主机端（服务端）SSH 支持

DSH-Phone 通过 SSH 隧道接入主机端，因此主机端需要能接受 SSH 连接：

- **Linux 主机**：原生支持 SSH（OpenSSH 服务端通常已内置或 `apt install openssh-server` 即可），开箱即用，无需额外安装。
- **Windows 主机**：建议下载安装 **OpenSSH 作为服务端**（Windows 设置 → 可选功能 → 添加"OpenSSH 服务器"，或 `winget install Microsoft.OpenSSH.Beta`），并确认 SSH 服务已启动、防火墙放行 22 端口，即可配合端侧 DSH-Phone 的 SSH 隧道建立与使用。

> 主机端 DSH 默认监听 `127.0.0.1:3080`，仅 loopback 访问；DSH-Phone 通过 SSH 隧道把手机本机端口转发到主机端，使 WebView 以 loopback 身份访问，从而获得完整功能。

## Zcode 模式与 zcode-phone-server

Zcode 模式的对端是独立仓库 [zcode-phone-server](https://github.com/liangjianzeng/zcode-phone-server)（嵌套在 DSH-Phone 工作区下的桥接服务，默认远端端口 **8787**）：它在电脑上以 stdio 驱动 ZCode 桌面引擎（`zcode.cjs` app-server），封装成 token 鉴权的 HTTP/SSE 服务，并自带一套移动优先的聊天 Web 页面。

**为什么必须有它**——DSH-Phone 的 Zcode 模式没有它就无服务可连：

1. **引擎没有可访问的入口**：ZCode 引擎（app-server）是桌面端内的 stdio 进程，官方不提供任何可直接访问的 web/移动端服务；手机无法直连。
2. **协议无法由浏览器直接说**：stdio 上的 ND-JSON 帧强约束（strict schema、必须先 `session/subscribe` 才有事件、账号授权要主动推送、引擎反向请求必须应答），这些只能在本地桥进程里完成。
3. **手机场景需要引擎没有的能力**：token 鉴权、断线重放（SSE 重放环 + delta 合帧）、运行中排队补发、429 限流自动重试（余额类错误识别不重试）、权限/提问转发手机人工、桌面任务索引同步（共享 sqlite 对账）、移动优先聊天页（事件/轮询双通道跟随、部件通道唯一事实来源、主题、回合结束线、复制分享）。
4. **与桌面共存而非替代**：共享桌面 ZCode 的凭据（免重新登录）与会话库——手机和桌面看到同一批会话，可互相旁观任务进度；桌面跑的任务手机能实时跟看。

工作方式：SSH 隧道把手机本地端口转发到电脑 `127.0.0.1:8787`，WebView 加载 `http://127.0.0.1:<localPort>/?token=<token>`；App 端 JS 桥与页面靠 DOM 约定协作（运行哨兵词、批准/拒绝按钮文案、成果 chip、composer 注入点），DSH/Zcode 两个模式共用同一套桥脚本，App 侧几乎零改动。

## 快速开始

### 构建 APK

推荐用仓库自带的一键脚本（先自检环境，再构建）：

```bash
tool/build_apk.sh                # release APK（默认只 AOT arm64）
tool/build_apk.sh --check        # 只自检：SDK / JDK 17 / gen_snapshot / 签名是否齐
tool/build_apk.sh --debug        # debug 包（JIT，不需要 AOT 快照生成器）
```

等价的手动命令：

```bash
flutter pub get
dart run flutter_launcher_icons        # 从 icon/logo.png 生成启动图标
flutter build apk --release --target-platform=android-arm64
```

产物：`build/app/outputs/flutter-apk/app-release.apk`（发版时上传 GitHub Releases，仓库不提交 APK 二进制）

打包环境按平台见 [BUILD.md](BUILD.md)（[Windows](BUILD.windows.md) / [Linux、macOS、CI](BUILD.linux.md)），两条通用注意：

- **release 签名**：需要 `android/key.properties` + `key.jks`（不入库）。缺失时 `build.gradle` 会**静默回退 debug 签名**——能装机自测，但不能覆盖安装已发布的正式版，也不要拿去发版。
- **aarch64 Linux 打包机**（ARM 服务器 / Jetson / DGX 等）：Google 不发 linux_arm64 的 aapt2 / NDK clang，Flutter 也不发 arm64 Linux 主机的 Android AOT `gen_snapshot`，需一次性安装 amd64 多架构运行库与 FEX 模拟器，再用 `tool/build_apk.sh --fix-artifacts` 补齐官方产物（自动包一层 FEX 包装，因为 qemu-user 跑 `gen_snapshot` 会自身崩溃）。清单与报错对照表见 [BUILD.linux.md](BUILD.linux.md)。

### 使用

1. 首次打开 → 配置 SSH 地址（如 `100.81.83.59`）、用户名（如 `jianzengliang`）、认证方式与本地端口（默认 `3081`）；最多可配置 3 路实例。
2. 保存并连接，隧道建立后自动加载 `http://127.0.0.1:3081` 的 DSH Web UI。若服务端启用了 token 鉴权（访问提示 `dsh web authentication required`），先在设置对应实例填入 DSH 启动时打印的 `?token=` 值。
3. 顶栏：实例切换器（点当前实例标签弹菜单换实例，别名过长自动省略）+ 连接状态（点一下 = 立即探活/重连）+ 模式切换（仅当该实例开了 Zcode 或 WorkBuddy 时出现）+ Unsloth Studio 入口 + GitHub 入口（两者按全局开关显示）+ 设置入口（**始终钉在最右**，图标再多也不会被挤出屏幕，其余图标过宽时横向滚动）。设置页含 SSH 配置、DSH 访问 Token、服务模式与远端端口、**连接诊断**、Unsloth Studio 配置、GitHub 仓库快捷访问开关（PAT 令牌可在 GitHub 页面内直接填写）、加载超时、界面开关（缩放控件 / 相机入口 / 语音输入入口 / 天气动效 / 日出日落联动）、月相观测位置、上传大小上限、关于信息。

> 说明：远程 DSH 默认只监听 `127.0.0.1:3080`，且配置类接口（如 `settings.describe`）被设计为仅 loopback 访问。DSH-Phone 通过 SSH 隧道把手机本机端口转发到远程，使 WebView 以 loopback 身份访问，从而获得完整功能。
>
> 提示：隧道吞吐受运营商 QoS 影响——**跨运营商时 UDP 可能被限速/丢包**，导致加载超时；同一运营商下通常可达数 MB/s 且不丢包。遇到慢/超时可尝试切换网络或调大加载超时。
